# Московский молодёжный

## Онлайн-демо без сервера

**Сайт: https://leethoof1.github.io/ForumMM/**

GitHub Pages публикуется автоматически из `main` через `.github/workflows/pages.yml`. В этом режиме прогресс хранится только в памяти открытой страницы: переключение вкладок сохраняет его, перезагрузка сбрасывает баланс, задания и историю. Cookie и localStorage не используются. Все обмены тестовые. Тестовое слово видно в окне каждого задания; это публичные демонстрационные слова, они не связаны с закрытыми серверными кодами.

Локальная сборка: `python3 tools/build_pages.py`, затем `python3 -m http.server 8020` и открытие `/dist/`. Папка `dist` содержит только интерфейс и `data.json`, без Python-сервера, БД и файлов секретов. Проверка: `python3 tests/pages_smoke.py` (Python Playwright и Chromium). Программа, площадки и магазин редактируются в `data.json`; push в `main` обновляет сайт.

Ниже описан дополнительный серверный режим с сохранением прогресса; он остаётся доступен для дальнейшего развития и не требуется для GitHub Pages.

Мобильная демоверсия форума 27 ноября 2026 года. Программа, задания по кодовым словам и тестовый магазин. Без регистрации и установки. Python 3.12+, SQLite, HTML/CSS/JS; runtime-зависимостей нет.

## Запуск

```sh
cd /workspace/ForumMM
export FORUM_STATE_DIR=/workspace/forummm-state
python3 server.py --port 8000
```

Откройте приложение на порту 8000. При первом запросе сервер создаёт случайный идентификатор сессии в HttpOnly/SameSite cookie. Баланс, выполненные задания и история хранятся только в SQLite. После очистки cookie начинается новая сессия. Это демо без идентификации: смена браузера позволяет начать заново.

В каталоге `FORUM_STATE_DIR` (по умолчанию `~/.local/share/forummm`) сохраняются `progress.sqlite3` и закрытый `codes.json`. При первом старте создаются 10 случайных тестовых кодов. Передайте этот файл организатору отдельно по закрытому каналу; не публикуйте в GitHub. Изменение кода не сбрасывает выполненные задания. Существующий файл никогда не перезаписывается. В репозитории и публичном API кодов нет; тела запросов не журналируются.

## Редактирование

Единый файл `data.json`:

- `event`: дата, часовой пояс, адрес, часы форума и место. Адрес меняется только здесь.
- `venues`: общие записи площадок для событий и заданий.
- `events`: время, название, описание, `venue`; необязательные `room`, `speaker`, `task`. `demo: true` отмечает пример. Общие события используют `venue: null` и остаются видны при фильтрации.
- `tasks`: `id`, название, действие, площадка, награда; `event` может быть null.
- `products`: идентификатор, название, цена, иконка, описание.

Правки данных читаются без перезапуска при обновлении страницы. Используйте уникальные стабильные ID; цены — положительные целые числа. Секретный `codes.json` сопоставляет ID заданий и слова. Сравнение игнорирует регистр и пробелы по краям. После 20 попыток в минуту действует ограничение. PNG логотипа в исходных вложениях не было; текущий знак — временная типографическая композиция. Для замены положите согласованный PNG в `public/logo.png` и замените `.brandmark` в `public/index.html` на изображение.

Демо-время на вкладке программы относится к дате форума: задайте 12:15 для параллельных активностей. «Реальное время» возвращает часы устройства; расчёт использует UTC+03:00 (Europe/Moscow). Интервалы включают начало и исключают конец. Проверка каждые 15 секунд и при возврате на вкладку. В рабочей презентации часы устройства должны быть выставлены верно.

## Проверки

```sh
python3 -m unittest discover -s tests -v
node --check public/app.js
```

API-тесты стартуют отдельный сервер с временной БД: неверное/верное слово, повторные и параллельные начисления, атомарные конкурирующие обмены, повтор одного ID обмена, недостаточный баланс, изоляция сессий и отсутствие кодов в публичном API.

Мобильный сценарий проверен Chromium в viewport 390×844: программа → 12:15 → связанное задание → неверное/верное слово → обновление → наклейка → история после обновления → недостаточный баланс. Проверены границы 13:30 и 17:00. Проверка на физическом телефоне и вход по реальному QR остаются после публикации.

## Публикация и общий QR

Готов `Dockerfile`. Нужен хостинг контейнера с HTTPS, доменом и **постоянным диском `/state`**. Один экземпляр приложения; SQLite не размещать на сетевом файловом хранилище. HTTPS reverse proxy должен передавать cookie; `FORUM_SECURE_COOKIE=1` включается в контейнере. Для локального HTTP эту переменную не включайте. Бэкапируйте БД через SQLite backup API и отдельно `codes.json`. Сервер stdlib подходит для демо; перед массовым мероприятием нужны нагрузочная проверка, production HTTP-прокси, мониторинг и решение организаторов по выдаче мерча.

Публичный хостинг в этом чате не подключён, поэтому внешняя ссылка и настоящий QR пока не созданы. После получения URL:

```sh
python3 -m venv /tmp/forum-qr-env
/tmp/forum-qr-env/bin/pip install qrcode==8.2
/tmp/forum-qr-env/bin/python tools/qr.py https://YOUR-DOMAIN/ --output /tmp/forum-qr.svg
```

QR ведёт на корень сайта — по умолчанию открывается программа. В QR нет идентификатора участника. Нужны предоставленный HTTPS-домен/хостинг и постоянное хранилище; никаких секретов в чат отправлять не требуется. Изменения подготовлены локально; push в GitHub и публикация среды не выполнялись.

Повтор браузерного smoke-теста (нужны Python Playwright и `/usr/bin/chromium`; сервер должен работать с указанным каталогом состояния):

```sh
FORUM_STATE_DIR=/workspace/forummm-state python3 tests/mobile_smoke.py
```

Тест использует новую браузерную сессию, читает тестовое слово из закрытого файла и не выводит его. Скриншоты сохраняются в `/tmp/forummm-test-artifacts`.
