# Московский молодёжный — форум 2026

Рабочее приложение форума 27 ноября 2026, 10:00–17:00 (Europe/Moscow), КДЦ «Московский», Московский проспект, 152. Python 3.12+, SQLite, HTML/CSS/JS, для QR экрана голосования нужен qrcode (apt: python3-qrcode; pip: qrcode==8.2). База хранится на VPS, cookie содержит только идентификатор анонимной сессии.

## Запуск и данные

```sh
export FORUM_STATE_DIR=/private/forummm
python3 server.py --port 8090
```

Программа редактируется в `data.json`: `event`, `venues`, `events`, `products`. Шесть фильтров площадок: «Мы — граждане России», «Мы за безопасную среду», «Мы — добровольцы», «Мы верим в Россию», «Мы едины», «Основная программа». Все добровольческие мероприятия — в кабинете 202, конкурс защиты проектов удалён. «Мы едины» — банкетный зал, 12:30–14:00 и 14:30–17:00. Регистрация и прочая общая программа, включая интерактивную выставку с точками активности, — в «Основной программе». Демо-времени и тестового режима нет, статус обновляется каждые 10 секунд и при возвращении на страницу. Часы телефона должны быть верными.

Во вкладке заданий только общий ввод кода. Устаревшие `tasks`/API `/api/complete` сохранены для совместимости прежних кодов и записей в БД, но не показываются участникам. Рабочее начисление использует `/api/redeem`.

## Коды участия

100 уникальных кодов: 5 с лимитом 600, 15 с лимитом 100, 80 с лимитом 10. Каждый даёт +1 балл, всего 5300 возможных начислений. Один и тот же код — не более одного начисления на сессию браузера. Лимиты общие, проверка лимита и начисление атомарны. Повтор запроса не начисляет повторно. Коды общего пула не привязаны к площадке.

```sh
FORUM_STATE_DIR=/private/forummm python3 tools/manage_codes.py pool --output /private/forum-codes.csv
FORUM_STATE_DIR=/private/forummm python3 tools/manage_codes.py import-pool /private/forum-codes.csv
FORUM_STATE_DIR=/private/forummm python3 tools/manage_codes.py stats
```

Повторный импорт той же партии не сбрасывает расход. CSV и TXT со словами хранить вне репозитория, не публиковать. В БД только хеши и журнал применений. TXT, переданный организатору, содержит ту же партию, что исходный CSV. Старые одноразовые коды и история не удаляются при обновлении.

## Выдача мерча на телефоне участника

1. Участник подтверждает обмен — сервер списывает баллы и создаёт обмен с номером получения.
2. В истории: «Баллы списаны» и приглашение подойти к организаторам в зону регистрации.
3. Участник передаёт телефон сотруднику. В истории сотрудник нажимает «Подтверждение выдачи организатором» и вводит общий закрытый код.
4. Сервер проверяет код и принадлежность обмена этой сессии, атомарно записывает время выдачи. В истории появляется «Мерч получен». Повторная отправка не создаёт повторную выдачу.

Кабинет и регистрация сотруднику не нужны. Код выдачи автоматически создаётся в `FORUM_STATE_DIR/delivery-code.txt` (0600) при первом старте новой версии. На VPS владелец смотрит его командой `cat /var/lib/forummm/delivery-code.txt` и сообщает только сотрудникам. Код не содержится в GitHub или пользовательском API и не сохраняется в браузере. Он отличается от 100 кодов начисления и от прежнего ключа страницы `/staff`. Для защиты от подбора — 5 неверных попыток в минуту на сессию и nginx rate limit по IP.

Если код подсмотрели, его нужно заменить в закрытом файле. Редактировать можно без перезапуска сервиса. Код подтверждения нельзя публиковать на стенде или сообщать участникам; сотрудник вводит его сам. Для рабочей выдачи обязательно HTTPS. Страница `/staff` сохранена как альтернативный инструмент сотрудников, но для описанного сценария не используется.

Подтверждение защищает конкретный обмен от повторной выдачи, а не ограничивает число покупок одним физическим человеком. За новые баллы можно приобрести другой товар; каждый товар — однократно. Очистка cookie создаёт новую анонимную сессию, поэтому балансы между браузерами не переносятся.

## Обновление VPS и резервные копии

`deploy/update-vps.sh FULL_COMMIT /var/lib/forummm/forum-codes.csv` — останавливает сервис, создаёт SQLite backup, обновляет версию и импортирует ту же партию. Использования кодов, балансы и история сохраняются. При ошибке возвращает предыдущую версию исходников; путь к backup выводится в консоль. Данные находятся в `/var/lib/forummm`, исходники в `/opt/forummm`. `deploy/forummm.service` запускает непривилегированного пользователя; `deploy/nginx.conf` проксирует только приложение и ограничивает частоту API-запросов.

Первичный `deploy/install-vps.sh` рассчитан на первоначальную проверку по HTTP. До запуска форума настроить домен/HTTPS и удалить `/etc/systemd/system/forummm.service.d/initial-http.conf`, затем перезапустить сервис для Secure cookie. База и закрытые файлы не должны раздаваться nginx. Перед форумом запланирован отдельный согласованный сброс тестового прогресса с backup; обновление версии само по себе ничего не обнуляет.

GitHub Pages теперь содержит ссылку на действующий сервер, без отдельного тестового баланса. В корневом `index.html` установлена ссылка https://mm2026.ru/; HTTPS и Secure cookie подтверждены внешним запросом. Не направляйте QR форума на старые тестовые версии.

## Тематические кодовые слова

Рабочие слова и их распределение хранятся только в закрытых `forum-words.csv` и `forum-words.txt`, вне GitHub. В CSV добавлена колонка `location` для организаторов: открытие и пленарка — 5 слов по 600 применений, пять секций — по 3 слова (15 по 100), десять выставочных направлений — по 8 слов (80 по 10). Места в файле — план выдачи; технически ввод остаётся общим.

Регистр, пробелы по краям и различия Е/Ё игнорируются. Нормализация применяется перед хешированием. Сами слова не отдаются в API. Для перехода без потери прогресса: `tools/manage_codes.py replace-pool /private/forum-words.csv`. Импорт и отключение прежних общих партий выполняются в одной транзакции. Баланс, история и журнал уже использованных кодов сохраняются. Повторная замена той же партией не сбрасывает расход. Обычный `import-pool` не включает ранее отключённую партию обратно.

Установка: `deploy/update-vps.sh FULL_COMMIT /root/forum-words.csv replace`. Скрипт сохраняет новый файл как `/var/lib/forummm/forum-words.csv`, старый `forum-codes.csv` не удаляет и не перезаписывает. Обновление по-прежнему делает backup БД. Чтобы установить выбранное организатором слово подтверждения, замените содержимое `/var/lib/forummm/delivery-code.txt` на сервере, сохранив владельца `forummm` и права 0600. Значение не хранится в GitHub и не связано с партиями начисления.

## HTTPS для mm2026.ru

После публикации A-записей mm2026.ru и www.mm2026.ru на 87.228.63.164 запустите на VPS от root `bash deploy/enable-https.sh`. Необязательный первый аргумент — email для аккаунта Let’s Encrypt; без него регистрация выполняется без email. Скрипт устанавливает Certbot из apt, сохраняет копию конфигурации nginx, меняет server_name только у сайта forummm, выпускает сертификат для обоих имён, включает HTTP→HTTPS, проверяет сертификат и API с корректным SNI, отключает временный HTTP override и проверяет Secure/HttpOnly cookie. Затем включает certbot.timer и выполняет `certbot renew --dry-run`. TLS-проверка не отключается. Должны быть доступны внешние TCP 80 и 443; NAT и firewall провайдера скрипт не меняет.

Если выпуск сертификата не прошёл, конфигурация сайта возвращается из копии. Если не прошла только проверка продления, уже выпущенный сертификат остаётся установленным — нужно проверить вывод. Смена IP-адреса сайта на домен создаёт новую браузерную сессию; предыдущая БД не стирается, но cookie с IP на домен не передаются.

## Магазин и защита по IP (обновление 25 ноября)

Рабочая позиция — «Набор участника форума»: шоппер, блокнот и ручка, 6 баллов. Один товар можно приобрести один раз на сессию; при включённой IP-защите — также один раз с IP-адреса. Повтор того же запроса обмена остаётся идемпотентным, другие повторные покупки отклоняются без списания. Старые обмены сохранены и учитываются для старых ID товаров.

Остатки в `products[].stock`: `total=700`, `initial=500`, `release_at=2026-11-27T14:00:00+03:00`. Поле можно менять при согласовании расписания. Все 700 входят в общий лимит; в 14:00 открывается суммарная квота 700, а не добавляется новая независимая партия поверх проданных наборов. Пока доступно 500, каждое подтверждение обмена резервирует один набор и уменьшает доступность. Выдача по коду организатора переводит резерв в выданный и уменьшает «Осталось к выдаче» с 500 до 499 до 14:00; после 14:00 счётчик расширяется до 700 минус уже выданные наборы и далее. Отсутствие выдачи не возвращает резерв автоматически. Магазин обновляет данные каждые 10 секунд и при возврате на страницу. Покупка, резерв, проверка остатка и списание происходят в одной транзакции — одновременные запросы не превышают квоту.

Счётчики API: `available` — доступно для нового обмена, `reserved` — куплено и ожидает выдачи, `issued` — уже выдано, `remaining` — ещё не выдано из уже открытой партии (включая резервы). Будущая партия, её время и объём не возвращаются в публичном API; полная конфигурация stock также исключена из публичного каталога. Это разные величины; выдача уже оплаченного набора не уменьшает `available` повторно.

`FORUM_IP_GUARD=1` включает общий запрет повторного применения кода и повторной покупки товара с одного IP даже при новом браузере/инкогнито. Дополнительно действует прежняя защита сессии: смена IP в том же браузере не даёт повторный балл или покупку. Баланс и история остаются привязанными к приватной сессии, не объединяются по IP — иначе абоненты с одним IP увидели бы чужую историю. Старые запросы до установки этой версии нельзя задним числом привязать к IP, который тогда не сохранялся.

IP — не идентификатор человека или устройства: мобильный оператор может выдавать общий внешний IP разным абонентам (CGNAT), а один абонент может менять IP. Строгий режим может ошибочно отказывать разным людям, даже без Wi-Fi; это принятое ограничение текущего режима, а не полная защита от повторного участия. Отключатель: в `/etc/systemd/system/forummm.service.d/ip-guard.conf` изменить `FORUM_IP_GUARD=1` на `FORUM_IP_GUARD=0`, затем `systemctl daemon-reload && systemctl restart forummm`. Защита сессии, единоразовая покупка и складские квоты останутся.

В прикладной БД сохраняется HMAC IP с постоянным закрытым ключом `FORUM_STATE_DIR/ip-key.txt`, а не исходный IP. Ключ нужно сохранять вместе с backup базы: его замена изменит идентификаторы адресов. Обычные nginx access logs имеют отдельные настройки. Клиентский заголовок X-Real-IP учитывается только при `FORUM_TRUST_PROXY=1` и запросе от loopback reverse proxy. Внешний запрос напрямую к backend не может подменить свой IP заголовком. Backend в systemd слушает только 127.0.0.1:8090; nginx должен перезаписывать X-Real-IP своим `$remote_addr`. Скрипт обновления проверяет эту настройку и ставит отдельный systemd override. Установку нужно выполнять через этот скрипт, а не только git checkout, иначе старый сервис не получит новую конфигурацию доверенного proxy.

Программа открывается в «Основной программе». Фильтра «Весь форум» и ссылок на ввод кодов в событиях больше нет. Шесть кнопок секций видны сеткой под описанием форума и перед ближайшим событием. Ближайшее и текущие события относятся только к выбранному разделу. Ввод кода — только во вкладке «Задания».

При обычном обновлении теперь достаточно `bash deploy/update-vps.sh FULL_COMMIT`: существующий CSV в /var/lib/forummm определяется автоматически (сначала forum-words.csv, затем forum-codes.csv). Режим по умолчанию — импорт без изменения активности других партий и без сброса расхода.

## Закрытое голосование пленарки

Вопрос: «Кто кого сегодня лучше понимает?» Варианты: «Взрослые лучше понимают молодёжь» и «Молодёжь лучше понимает взрослых». Модуль `polls.py`, отдельные страницы `/vote`, `/results`, `/poll-admin`; в главном меню их нет. При первом старте создаётся закрытое голосование с тремя разными случайными ключами. Приватный файл `/var/lib/forummm/poll-links.json` содержит полные ссылки:

- `vote` — участники, открывают по QR. Один неизменяемый голос на сессию браузера. После обновления голос остаётся. Повтор той же отправки не добавляет голос; попытка сменить вариант отклоняется.
- `results` — экран/проектор: живые количества и проценты, общий счётчик и автоматически созданный QR со ссылкой `vote`. Обновление каждые 2 секунды.
- `control` — только ведущий/организатор: открыть, закрыть, посмотреть результаты, отдельно сбросить голоса с явным подтверждением. Начальное состояние — закрыто.

Ссылки имеют ключ после `#`: ключ не отправляется в URL запроса, не попадает в обычный nginx access log или Referer. JavaScript передаёт его в теле POST только нужному API. Ключи ролей не взаимозаменяемы; страница без полного ключа не даёт данных. Раздавайте участникам только QR/ссылку `vote`, на проекторе открывайте `results`, а `control` никому не показывайте. Ссылки не защищают от пересылки тем, кто их получил. HTTPS обязателен.

Без идентификации нет гарантии «один физический человек — один голос»: новый браузер/очистка cookie позволяет новую сессию. По умолчанию `FORUM_POLL_IP_GUARD=0`, независимо от антинакрутки мерча: мобильные операторы могут разделять IP между абонентами, поэтому IP-ограничение может ошибочно отсечь аудиторию. При явном решении организаторов можно включить `FORUM_POLL_IP_GUARD=1`. Баллы за голос не начисляются.

Сервер использует SQLite WAL и максимум 32 рабочих обработчика, очередь соединений 1024. У `/api/poll/` отдельный лимит nginx 250 запросов/сек на IP с burst 1000, чтобы 600 участников могли голосовать даже через общий адрес оператора. Остальные API сохраняют прежние лимиты. Обновляющий скрипт сохраняет копию nginx-конфигурации и добавляет маршрут, сохраняя существующий HTTPS; проверяет nginx -t перед reload. В тестовой среде проверены 600 одновременных голосов (300/300) и 600 повторов без увеличения счётчика. Это не замер производительности VPS; перед форумом проверку стоит выполнить на VPS.

Для локальной проверки на отдельной БД (тест перезапускает/обнуляет только свой опрос): `FORUM_STATE_DIR=/private/test python3 tests/load_poll.py`, нужен aiohttp и запущенный loopback-сервер на 8101. Тест браузера: `FORUM_STATE_DIR=/private/test python3 tests/poll_smoke.py` (Playwright, Chromium, qrcode на сервере). Корректный public base URL задаётся `FORUM_PUBLIC_URL`, по умолчанию https://mm2026.ru.

## Сброс тестового прогресса

Запрошенный сброс проводится отдельным действием, не каждым обновлением. Владелец запускает скрипт обновления с аргументами `FULL_COMMIT "" import reset`. Сервис остановлен на время backup и сброса, затем запускается. `tools/reset_progress.py --confirm RESET-PROGRESS` создаёт отдельную SQLite-копию с правами 0600, обнуляет балансы, историю обменов, резервы, использование слов, ограничения покупок и IP-счётчики. Сессии сохраняются с нулевыми балансами, сами кодовые слова, лимиты и активность партий сохраняются. Обычный прогресс-API после обновления страницы уже не показывает старую историю.

Опрос независим: этот сброс НЕ удаляет голоса опроса, ссылки или его состояние. Для тестовых голосов — отдельная кнопка в control. Ключ выдачи, IP-ключ и все конфигурационные секреты не меняются. На целевом VPS сброс считается выполненным только после успешного запуска команды владельцем, не после сохранения кода в GitHub.
