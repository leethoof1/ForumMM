# Московский молодёжный

## Онлайн-демо без сервера

**Сайт: https://leethoof1.github.io/ForumMM/**

GitHub Pages публикуется автоматически из корня `main` (Settings → Pages → Deploy from a branch). Корневой `index.html` открывает интерфейс из `public` в браузерном режиме. При изменении разметки `public/index.html` синхронизируйте её с корневым `index.html`, сохранив `data-mode="browser"` и пути `./public/`. В этом режиме прогресс хранится только в памяти открытой страницы: переключение вкладок сохраняет его, перезагрузка сбрасывает баланс, задания и историю. Cookie и localStorage не используются. Все обмены тестовые. Тестовое слово видно в окне каждого задания; это публичные демонстрационные слова, они не связаны с закрытыми серверными кодами.

Локальная сборка: `python3 tools/build_pages.py`, затем `python3 -m http.server 8020` и открытие `/dist/`. Папка `dist` содержит только интерфейс и `data.json`, без Python-сервера, БД и файлов секретов. Проверка: `python3 tests/pages_smoke.py` (Python Playwright и Chromium). Программа, площадки и магазин редактируются в `data.json`; push в `main` обновляет сайт.

Ниже описан дополнительный серверный режим с сохранением прогресса; он остаётся доступен для дальнейшего развития и не требуется для GitHub Pages.

Мобильная демоверсия форума 27 ноября 2026 года. Программа, задания по кодовым словам и тестовый магазин. Без регистрации и установки. Python 3.12+, SQLite, HTML/CSS/JS; runtime-зависимостей нет.

## Запуск

```sh
cd /workspace/ForumMM
export FORUM_STATE_DIR=/workspace/forummm-state
python3 server.py --port 8090
```

Откройте приложение на порту 8090. При первом запросе сервер создаёт случайный идентификатор сессии в HttpOnly/SameSite cookie. Баланс, выполненные задания и история хранятся только в SQLite. После очистки cookie начинается новая сессия. Это демо без идентификации: смена браузера позволяет начать заново.

## Одноразовые коды (серверный режим)

Данные участников и таблица `redeem_codes` хранятся в `FORUM_STATE_DIR/progress.sqlite3`. У каждого кода есть хеш SHA-256, задание, партия, дата создания, использовавшая сессия и время погашения. Один код даёт балл только один раз для всех браузеров. Один участник получает награду за задание один раз. Неверное задание не погашает код; повтор уже выполненного задания не сжигает следующий код. Погашение, запись выполнения и изменение баланса выполняются в одной транзакции SQLite `BEGIN IMMEDIATE`.

Старые общие слова из `codes.json` больше не принимаются, файл не импортируется. Существующие балансы и история при обновлении сохраняются. Новые коды автоматически при старте не выпускаются. Серверная версия не показывает тестовые слова; GitHub Pages остаётся отдельной демонстрацией без общей базы.

Выпускайте коды **на рабочем сервере**, от имени пользователя приложения с тем же каталогом БД:

```sh
cd /opt/forummm
sudo -u forummm env FORUM_STATE_DIR=/var/lib/forummm python3 tools/manage_codes.py generate --per-task 100 --output /var/lib/forummm/codes-batch-01.csv
sudo -u forummm env FORUM_STATE_DIR=/var/lib/forummm python3 tools/manage_codes.py stats
```

`--per-task 100` создаёт 100 кодов для каждого из 10 заданий. Для одной площадки/задания добавьте `--task t0` (можно повторять флаг). Количество можно выбрать позднее, новые партии не отменяют старые. CSV содержит название задания и коды для печати. Он создаётся с правами 0600 вне репозитория; существующий файл не перезаписывается. Открытый текст кодов не хранится в БД и не возвращается API. Сохраните CSV безопасно: восстановить коды из хешей нельзя.

Коды содержат 80 случайных бит. Регистр и пробелы по краям игнорируются; дефисы нужно сохранять. Организатор выдаёт отдельный код участнику **после выполнения задания**. Передать неиспользованный код другому человеку всё ещё возможно: балл получит тот, кто введёт его первым. Авторизации личности пока нет. После удаления cookie баланс не восстанавливается, но использованный код остаётся погашенным для всех.

## Развёртывание на VPS

Шаблоны: `deploy/forummm.service` (systemd, непривилегированный пользователь) и `deploy/nginx.conf` (reverse proxy, ограничение запросов по IP). Установите Python 3.12+, nginx; разместите код в `/opt/forummm`, создайте системного пользователя `forummm`, установите unit и включите сервис. Nginx проксирует только приложение, не выдаёт каталог исходников или БД. Для выбранного домена получите HTTPS-сертификат и добавьте HTTPS в nginx, прежде чем использовать сессии с `FORUM_SECURE_COOKIE=1`. Доступ к 8090 снаружи не нужен. Домен и доступ для установки согласуются отдельно.

Перед обновлением делайте согласованный backup SQLite через backup API. Перезапуск сервиса не очищает БД. 9 API-тестов покрывают в том числе одновременное погашение одним кодом разными участниками, перезапуск, неверное задание, ограничение попыток и генерацию CSV.

## Редактирование

Единый файл `data.json`:

- `event`: дата, часовой пояс, адрес, часы форума и место. Адрес меняется только здесь.
- `venues`: общие записи площадок для событий и заданий.
- `events`: время, название, описание, `venue`; необязательные `room`, `speaker`, `task`. `demo: true` отмечает пример. Общие события используют `venue: null` и остаются видны при фильтрации.
- `tasks`: `id`, название, действие, площадка, награда; `event` может быть null.
- `products`: идентификатор, название, цена, иконка, описание.

Правки данных читаются без перезапуска при обновлении страницы. Используйте уникальные стабильные ID; цены — положительные целые числа. Коды выпускаются утилитой `tools/manage_codes.py`. Сравнение игнорирует регистр и пробелы по краям. После 20 попыток в минуту действует ограничение. PNG логотипа в исходных вложениях не было; текущий знак — временная типографическая композиция. Для замены положите согласованный PNG в `public/logo.png` и замените `.brandmark` в `public/index.html` на изображение.

Демо-время на вкладке программы относится к дате форума: задайте 12:15 для параллельных активностей. «Реальное время» возвращает часы устройства; расчёт использует UTC+03:00 (Europe/Moscow). Интервалы включают начало и исключают конец. Проверка каждые 15 секунд и при возврате на вкладку. В рабочей презентации часы устройства должны быть выставлены верно.

## Публикация и общий QR

Готов `Dockerfile`. Нужен хостинг контейнера с HTTPS, доменом и **постоянным диском `/state`**. Один экземпляр приложения; SQLite не размещать на сетевом файловом хранилище. HTTPS reverse proxy должен передавать cookie; `FORUM_SECURE_COOKIE=1` включается в контейнере. Для локального HTTP эту переменную не включайте. Бэкапируйте БД через SQLite backup API и отдельно закрытые CSV со списками кодов. Сервер stdlib подходит для демо; перед массовым мероприятием нужны нагрузочная проверка, production HTTP-прокси, мониторинг и решение организаторов по выдаче мерча.

GitHub Pages работает в режиме без сервера. Рабочая версия с общей БД требует развёртывания на VPS. После получения URL:

```sh
python3 -m venv /tmp/forum-qr-env
/tmp/forum-qr-env/bin/pip install qrcode==8.2
/tmp/forum-qr-env/bin/python tools/qr.py https://YOUR-DOMAIN/ --output /tmp/forum-qr.svg
```

QR ведёт на корень сайта — по умолчанию открывается программа. В QR нет идентификатора участника. Нужны предоставленный HTTPS-домен/хостинг и постоянное хранилище; никаких секретов в чат отправлять не требуется. Исходники ведутся в GitHub. Доступность серверной версии и HTTPS подтверждаются отдельно после установки на VPS.

Повтор браузерного smoke-теста (нужны Python Playwright и `/usr/bin/chromium`; сервер должен работать с указанным каталогом состояния):

```sh
FORUM_CODES_CSV=/path/to/test-codes.csv python3 tests/mobile_smoke.py
```

Тест использует новую браузерную сессию, читает одноразовый код из закрытого CSV (для каждого запуска нужна новая партия) и не выводит его. Скриншоты сохраняются в `/tmp/forummm-test-artifacts`.

### Первоначальная установка через консоль владельца

Если SSH из среды разработки недоступен, владелец может выполнить `deploy/install-vps.sh` от root на **отдельном Ubuntu VPS**. Скрипт ставит Python/nginx, получает закреплённую серверную версию приложения, создаёт сервис и закрытый каталог SQLite, выпускает 20 тестовых одноразовых кодов (по 2 на задание). Существующий прогресс не сбрасывается. Другие обнаруженные сайты nginx и посторонний каталог приложения останавливают установку. Стандартный сайт nginx отключается с сохранением в `sites-disabled`.

Скрипт рассчитан на первоначальную HTTP-проверку по IP, НЕ на боевой запуск: временно отключает Secure cookie через `/etc/systemd/system/forummm.service.d/initial-http.conf`. После настройки HTTPS удалите этот override и перезапустите сервис, чтобы вернуть Secure cookie. Порты 80/443 на внешнем адресе должны вести к VPS. Правила firewall и NAT скрипт не меняет. Сам установщик нужно скачать из репозитория; `bash -n` проверяет его синтаксис, фактическое выполнение на целевом VPS ещё нужно подтвердить.

## Обновление 24 ноября: лимитированные коды и выдача мерча

Новый общий пул: **100 кодов — 5×600, 15×100 и 80×10**, всего 5300 начислений по 1 баллу. Каждый код даёт балл один раз на сессию браузера; повтор запроса идемпотентен. Лимит общий для всех участников и проверяется в одной транзакции с начислением. Очистка cookie создаёт нового участника — без регистрации привязки к физическому человеку нет. Общие коды могут передаваться до исчерпания лимита.

Коды общего пула не привязаны к конкретным заданиям: организатор распределяет их между активностями. Вкладка «Задания» содержит общий ввод; кнопки карточек в серверной версии ведут в этот же ввод. Старый API привязанных одноразовых кодов и их история сохранены для совместимости, но новые 100 кодов вводятся через `/api/redeem`.

Выпуск: `FORUM_STATE_DIR=/private/state python3 tools/manage_codes.py pool --output /private/forum-codes.csv`.
Импорт той же партии на VPS: `FORUM_STATE_DIR=/var/lib/forummm python3 tools/manage_codes.py import-pool /var/lib/forummm/forum-codes.csv`. Повторный импорт не восстанавливает исчерпанные лимиты. CSV и БД не должны попадать в GitHub; хранится только SHA-256 и журнал `code_uses`. Скрипт `deploy/update-vps.sh FULL_COMMIT /root/forum-codes.csv` создаёт backup SQLite, обновляет версию и импортирует CSV с сохранением прогресса.

После обмена в истории отдельно видны **«Баллы списаны»** и **«Ожидает выдачи организатором»**. Участник показывает случайный 16-значный номер получения. Организатор открывает `/staff`, вводит ключ из `/var/lib/forummm/staff-key.txt` (создаётся один раз, права 0600), находит обмен и подтверждает физическую выдачу. В истории участника после обновления появляется **«Мерч получен»** с временем. Повторное подтверждение не создаёт второй выдачи. Ключ хранится только в памяти вкладки и не попадает в пользовательский API. Использовать страницу сотрудников только по HTTPS. Это защита от повторной выдачи одного обмена, а не запрет нового обмена за новые баллы; ограничение мерча на человека требует отдельного правила и идентификации.

Миграции сохраняют старые сессии, историю, использованные одноразовые коды; старым обменам присваивается номер и начальный статус «ожидает выдачи». Если по старым обменам мерч уже физически выдан, сотрудник должен подтвердить эти выдачи перед открытием пункта.

Программа и спорные интервалы описаны в `docs/program-sources.md`. Цвета — синий, красный, белый; `public/logo.svg` — векторная реконструкция эмблемы, `public/district.svg` — городской силуэт. GitHub Pages остаётся демонстрацией без общей БД и без возможности подтверждать настоящую выдачу.
